# Авторизация выбранного устройства

MRP reader создаёт ControllerAuthorization на одно подключение. Каждая операция выбора получает AuthorizationContext в OutputRequest; worker передаёт его через prepare_authorized. PTP-обёртка сохраняет этот контекст и прежнюю проверку clock/group после подготовки.

Контекст не продлевает жизнь подключения. При его закрытии владелец отменяет активный обмен; ожидающая операция также отменяется при закрытии reply. PIN-окно открывается лениво, только при необходимости. На одно подключение допускается одно активное окно; разные подключения изолированы. Очереди сообщений/ответов ограничены четырьмя элементами, переполнение не маскируется.

StoredSessionPreparer::InteractivePinForUnpaired — явная политика: сохранённый ключ используется напрямую; иначе требуется контекст текущего запроса, PIN setup и сохранение ключа до Session::connect. При отмене/ошибке нет transient fallback. SavedOnly и AllowTransientForUnpaired сохраняют прежний смысл. Неверный сохранённый ключ не вызывает автоматическое PIN-пересопряжение.

PIN-окно ограничено90секундами, ожидание результата выбора в MRP —120секундами. Секреты не логируются. Ключ сохраняется по physical receiver UID; до переноса отображаемого имени из каталога окно использует этот UID как название. Последовательно выбранные новые получатели получают отдельные scope.

Это opt-in путь библиотеки. Default frontend и адаптер Станции не переведены автоматически. Подключение к реальным устройствам, установка и ввод PIN в iPhone не выполнялись. 170 автономных тестов прошли; полная wire-интеграция выбора→PIN→подготовленной медиасессии ещё требует отдельного сценария.
