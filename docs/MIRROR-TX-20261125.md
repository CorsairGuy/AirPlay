# Отправка зеркалирования AirPlay (TX) — 25.11.2026

> Историческая заметка о реализации. Сведения о базе ветки и тестах ниже относятся к моменту написания; текущее состояние — в [STATUS](STATUS.md).

Ветка `feat/mirror-tx` от актуального `origin/main` (`847fe38`).
Задача: отправлять подготовленные H.264-кадры и звук из приложения на
AirPlay-приёмник. Захват, кодирование и интерфейс остаются снаружи;
NTP/PTP-движок и FairPlay не изменялись.

## 1. Что уже было и что сверено

Существующий `media::tx` — рабочий отправитель AP2 realtime-звука: TCP,
transient/PIN-сопряжение, pair-verify, шифрованный управляющий канал,
SETUP/RECORD/TEARDOWN, RTP. Его `transport::{Connection, Rtsp}`, `pair` и
`crypto` переиспользованы как есть.

Сверка последовательности зеркалирования сделана по наблюдаемым реализациям
отправителя: doubletake (commit `5e2f1cbe…`, файлы `mirror.go`, `audio.go`,
`audio_frame.go`) и отчёт о tvpipe (tvpipe — производная от doubletake, а не
независимое подтверждение). Код не копировался; использованы только
наблюдаемые форматы.

Подтверждено наблюдением (не нормативной спецификацией):

| Шаг | Формат |
|---|---|
| Сопряжение | pair-verify (`POST /pair-verify`), далее управляющий канал шифруется ключами HAP |
| SETUP 1 | сессия (`deviceID`, `name`, `model`, `sourceVersion`, `sessionUUID`, `timingProtocol=NTP`, `timingPort`) + поток 96: `usingScreen=true`, `ct`, `spf`, `sr`, `audioFormat`, `shk` (32 байта), `latencyMax`, `streamConnections` |
| SETUP 2 | поток 110: `type`, `streamConnectionID`, `latencyMs`, `timestampInfo` |
| RECORD | по URI сессии, заголовок `Session` |
| Видеоканал | отдельный TCP к `dataPort`; 128-байтовый заголовок и тело |
| Кадр видео | ChaCha20-Poly1305, ключ HKDF-SHA512(общий секрет pair-verify, `DataStream-Salt<id>`, `DataStream-Output-Encryption-Key`), nonce — счётчик LE64, AAD — весь заголовок |
| Заголовок | `[0:4]` длина тела LE, `[4]` 0x00 кадр / 0x01 конфигурация, `[5]` 0x10 IDR, `[6]` 0x16 H.264 / 0x1e HEVC, `[7]` 0x01 у конфигурации, `[8:16]` NTP-время LE, `[40:48]` timeline ID |
| Звук | RTP: 12 байт, PT 0x60, SSRC 0, ChaCha20-Poly1305 с ключом `shk`, nonce — счётчик LE64 **в хвосте пакета**, AAD — поля timestamp и SSRC |
| TimeAnnounce | 20 байт, PT 0xd4, позиция RTP и время NTP |

Криптография совпадает с уже имеющимся приёмником: `crypto::aead` использует
IETF-nonce `0,0,0,0 + LE64`, что при нулевом счётчике блока эквивалентно
64x64-варианту, который применяют эти отправители.

## 2. API

```rust
use media::tx::mirror::{AudioFormat, MirrorAuth, MirrorConfig, MirrorSession, VideoCodec};

let mut config = MirrorConfig::new(endpoint, identity, MirrorAuth::Paired(Box::new(credentials)));
config.audio = AudioFormat::AAC_ELD;   // ct=8, spf=480
let mut session = MirrorSession::connect(config).await?;

session.send_video_config(VideoCodec::H264, &avcc_record, ntp_ts).await?;
session.send_video_frame(ntp_ts, 0, keyframe, &avcc_frame).await?;
session.send_audio_frame(rtp_time, &encoded_aac_eld).await?; // кадр уже сжат приложением
session.send_audio_sync(ntp_ts, rtp_time).await?;
session.heartbeat().await?;                                  // раз в секунду
session.stop().await?;                                       // TEARDOWN
```

- `PairingCredentials` берутся у существующего `PinPairing::finish(pin)` или
  из хранилища приложения; `MirrorAuth::Paired` выполняет pair-verify и
  выводит ключ видео из общего секрета. `MirrorAuth::Plain` — без
  сопряжения и шифрования, только для тестового приёмника.
- `send_video_frame` принимает AVCC (NAL с 4-байтовой длиной), метку NTP
  (32.32) и признак keyframe. `timeline != 0` (PTP) отклоняется: движок PTP
  не менялся.
- `send_audio_frame` принимает сжатый кадр (AAC-ELD/ALAC) и RTP-метку;
  seq и nonce ведёт сессия. Кодирование звука — обязанность приложения.
- `reconnect` пересоздаёт сессию с новыми идентификаторами потоков, заново
  выполняет SETUP/RECORD и повторно отправляет сохранённую конфигурацию
  кодека. `is_disconnected` замечает закрытие видеоканала.
- `stop` отправляет TEARDOWN и закрывает сокеты; `Drop` останавливает
  NTP-ответчик.

Границы: ядро не захватывает экран, не кодирует видео и звук, не решает,
когда менять разрешение, и не управляет громкостью приёмника.

## 3. Тесты

`cargo test -p media --test mirror_tx` — loopback-приёмник, который:

1. выполняет настоящий pair-verify (HAP), проверяет подпись контроллера;
2. проверяет порядок SETUP звука → SETUP видео → RECORD и ключи:
   `timingProtocol`, `shk` 32 байта, `usingScreen`, `ct`, `streamConnectionID`,
   `latencyMs`, `Session` в RECORD;
3. расшифровывает видеокадр ключом HKDF и проверяет AAD-заголовок, PTS и
   признак keyframe;
4. расшифровывает аудиопакет 0x60 (SSRC 0, nonce в хвосте) и TimeAnnounce;
5. закрывает видеоканал, требует обнаружения разрыва, переподключения с
   новыми stream ID и повторной отправки конфигурации;
6. принимает TEARDOWN.

Прогон: `cargo fmt --all`, `cargo clippy --workspace --all-targets --offline
-- -D warnings`, `cargo test -p media --test mirror_tx` — зелёные.

## 4. Проверка на реальном Apple TV (не выполнена)

Apple TV/Mac в этой среде нет, поэтому **фактическая картинка и звук на
приёмнике не подтверждены**. Успешный RX-тест ядра успехом TX не считается.

Пошаговая инструкция:

1. Сопрячь приёмник PIN-кодом через существующий `PinPairing` и сохранить
   `PairingCredentials`.
2. Захватить экран и кодировать H.264 (AVCC) и звук AAC-ELD снаружи; отправить
   конфигурацию, кадры и TimeAnnounce через `MirrorSession`.
3. Ожидаемый результат: Apple TV показывает экран, звук идёт синхронно;
   переподключение после разрыва восстанавливает картинку.
4. Записать: модель и tvOS, `/info` (features, sourceVersion), результат
   pair-verify, принятые SETUP-ответы (`dataPort`), первые 3 заголовка кадров,
   поведение при смене разрешения и после разрыва.
5. Если картинки нет: проверить, не отвергает ли приёмник заголовок с
   нулевыми полями геометрии (см. ограничения), и приложить дамп первых
   пакетов.

## 5. Ограничения и запросы на интеграцию

- **Не проверено на железе.** Ни один Apple TV не принимал этот поток.
- Поля геометрии в 128-байтовом заголовке (`APScreenProtocolHeader`) оставлены
  нулевыми: размер берётся из SPS. doubletake заполняет прямоугольники из
  метаданных кадра; нужно ли это конкретной tvOS — не установлено.
- Видео только H.264/H.265 в AVCC; смена разрешения — новый
  `send_video_config` от приложения. HEVC не проверялся.
- Звук: один кадр — один RTP-пакет, без RFC 2198 и без повторной отправки по
  запросу приёмника (NACK 0xd5). Для реального Apple TV может понадобиться
  история пакетов и RED.
- Время: TimeAnnounce и NTP-ответчик используют `timesync::ntp::now()`;
  PTP-timeline (`header[40:48]`) не поддерживается. **Запрос на интеграцию
  для NTP/PTP-владельцев:** нужен read-only интерфейс «текущее время и
  timeline ID квалифицированного домена» (для NTP — существующий, для PTP —
  когда движок будет готов), без изменения самого движка. Пока вызывающий
  передаёт метки сам, а PTP отклоняется явной ошибкой.
- FairPlay не используется и не изменялся: `ekey`/`eiv` не отправляются,
  видео шифруется ключом из pair-verify. Нужен ли Apple TV FairPlay именно
  для этого профиля, не установлено; doubletake допускает оба варианта.
- `MirrorAuth::Plain` существует только для тестового приёмника; это не
  рабочий профиль для Apple TV.
