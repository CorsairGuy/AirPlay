# Метаданные трека в sender-пути

Ветка `feat/tx-metadata` от `origin/main` (`847fe38`). В `main` не влита.

## Что добавлено

- `MetadataHandle` — клон watch-канала, который можно передать до старта
  сессии; `Session::metadata_handle()` отдаёт его наружу.
- `TrackMetadata`: `title`, `artist`, `album`, `artwork`, `position_frames`,
  `duration_frames`.
- `Artwork::Unchanged | Set { mime, data } | Clear`; очистка — отдельное
  состояние, чтобы пустое значение не означало «не менять».
- `TrackMetadata::validate`: тексты до 4096 байт без control-символов,
  позиция не больше длительности, обложка JPEG/PNG не больше 16 МиБ.
- При обновлении канал вызывает существующий RTSP `SET_PARAMETER`:
  - `mlit`/`minm`/`asar`/`asal` с `application/x-dmap-tagged`;
  - обложка отдельным запросом с её MIME, `Clear` — пустой JPEG;
  - `progress: 0/{position}/{duration}` с `text/parameters`.
- Канал опрашивается в существующем `control_owner`; второго протокольного
  движка или менеджера сессий нет. MRP-код не дублировался.

## Проверено протокольными тестами

`services/media/src/tx/session.rs`, модуль `metadata_tests`:
- DMAP-теги названия, исполнителя и альбома разбираются из тела;
- `Set` отправляет байты с MIME, `Clear` — пустое тело, `Unchanged` молчит;
- progress использует триплет кадров AirPlay;
- неверный MIME, позиция больше длительности и обложка > 16 МиБ
  отклоняются до отправки.

`cargo test -p media` — 77 тестов, все прошли.

## Ограничения

- **На реальном Apple TV или колонке не проверялось**: в окружении нет
  AirPlay-устройств. Проверены только формируемые протокольные тела.
- Смена трека, пауза, возобновление и очистка старой обложки поддержаны на
  уровне API (`Set`/`Clear`), но их поведение на приёмнике не наблюдалось.
- Позиция передаётся в кадрах 44,1 кГц, как в `progress`; пересчёт из
  времени трека остаётся за вызывающим.
