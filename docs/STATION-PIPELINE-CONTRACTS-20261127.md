# Runtime pipeline против источника: общие контракты и пробелы

Сравнение `runtime/src/pipeline/{pcm,buffered}.rs`, `services/media/src/tx/continuous*.rs`
и синтетического адаптера из `services/media/tests/station_adapter.rs` (C37).
Внешний `a1aefc79/docs/CORE_SENDER_ADAPTER.md` недоступен (HTTP 404), поэтому
срез Станции указан по локальной инвентаризации `STATION-CORE-GAPS-20261126.md`.

## Таблица контрактов

| Возможность | `continuous.rs` + `continuous_source.rs` | `runtime/src/pipeline/pcm.rs` | Станция (`a1aefc79`) |
| --- | --- | --- | --- |
| pause | `Timeline::pause`, тишина по расписанию, окно 600 с, `PauseExpired` | нет в API `run*`: только `stop` | есть в адаптере отправителя |
| seek | `invalidate_source`, новая генерация, `DiscardStale`, epoch не сбрасывается | нет; `run*` создаёт один epoch на запуск | G1: маркер перемотки в медиапотоке |
| EOF | gap grace 40 мс, затем тишина на той же шкале | вход `AsyncRead` закончился — запуск завершается | завершение источника |
| очередь | 512 слотов, stale-слоты, `bounded_reader` | `QUEUE_PACKETS = 64`, броадкаст | bounded reader |
| смена поколения | `State { generation, paused }` через watch | нет параметра состояния | поколение считает seek'и |
| объём | один производитель, много получателей | до 8 `--to`, все подключаются до старта часов | список получателей |
| управление | `SourceControl` в `services/remote` | `RelayControl`: громкость и наблюдение | 3-секундный deadline, coalescing |

Расхождение глубины очереди (512 против 64) не является ошибкой: `runtime`
работает в реальном времени и ограничивает задержку, источник держит запас на
grace/seek. Переносить 512 в runtime без изменения политики задержки нельзя.

## Чего не хватает в runtime

1. **Нет входа для pause/seek/EOF.** `run`, `run_controlled`, `run_selected*`,
   `run_with_local*` принимают только `AsyncRead` и `stop`. Пользователь
   pipeline не может передать `State`/поколение или перемотать без перезапуска
   всего запуска и нового epoch.
2. **Нет маркера перемотки.** Даже при внешнем seek `runtime` не выставляет
   признак поколения и не чистит очередь источника: это делает вызывающий код,
   если вообще делает.
3. **Нет публичного контракта для локального рендера при паузе.** `LocalSink`
   получает кадры, но пауза/тишина источника остаётся заботой вызывающего.

Пункт G3 (`STATION-CORE-GAPS-20261126.md`) остаётся открытым: подключение
единого runtime к источнику/контролю требует именно этих трёх контрактов.

## Что проверено

- `cargo test --offline -p media --test station_adapter` — 4 теста синтетического
  адаптера (pause/seek/EOF/необъявленная генерация), C37.
- `cargo test --offline -p runtime --lib pipeline` — существующие тесты pipeline
  (валидация опций, разбор адресов); они не покрывают pause/seek, потому что
  такого API нет.

## Границы

- Реальный адаптер Станции, Quasar/Glagol, ALSA, её конфиги и процесс не
  переносились и не проверялись.
- Сквозной запуск `runtime` с получателями требует сокетов и здесь не
  выполнялся; сравнение сделано по публичному API и коду.
- Устройство (iPhone/Apple TV/HomePod) недоступно.
