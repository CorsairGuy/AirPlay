# Независимые SDP-векторы AirPlay 1 (остаток P1 TX)

26 ноября 2026. Ветка `feat/airplay1-vectors` от `origin/main` `b612eb4`.

Аппаратной проверки нет: AirPort Express, Apple TV и iTunes/Mac недоступны; живой захват ANNOUNCE не снимался.

## Зачем

В ветке `feat/airplay1-auth` остался незакрытым пункт «независимые wire-векторы RSA/SDP». Для SDP это делается без устройства: у нас в одном ядре есть и отправитель (`tx::airplay1`), и приёмник (`media::raop`), поэтому расхождение между тем, что отправляется, и тем, что разбирается, ловится локально, если ожидаемые строки написаны руками, а не сгенерированы тестируемым кодом.

## Что сделано

- `tx::airplay1::sdp()` вынесен из метода сессии в свободную функцию `sdp(local, ssrc, codec, Option<(&[u8], &[u8])>)`; метод `Session::sdp` только передаёт свои поля. Поведение не изменилось, но сборку SDP теперь можно проверять без сети.
- `media::raop::parse_sdp` и `SdpError` стали `pub(crate)`, чтобы тест мог прогнать SDP отправителя через приёмник того же ядра.
- Новые тесты (`services/media/src/tx/airplay1.rs`):
  - `sdp_vectors_match_the_declared_profile` — точное сравнение с рукописной строкой для L16 (полный SDP, SSRC `0x01020304` → `16909060`, `IP4 127.0.0.1`), окончание для AppleLossless с `fmtp`, и шифрованный вариант с `a=rsaaeskey:AAAAAAAAAAAAAAAAAAAAAA` / `a=aesiv:AAECAwQFBgcICQoLDA0ODw` (base64 без padding);
  - `receiver_parser_accepts_the_sender_sdp_vectors` — приёмник разбирает L16 как `Pcm { frames_per_packet: 352 }`, 44.1 кГц, 2 канала; ALAC как `Alac { bit_depth: 16, frames_per_packet: 352 }`; шифрованный SDP отвергается, потому что приёмник умеет только открытый профиль.

## RSA: что честно закрыто, а что нет

Полностью независимый known-answer вектор для RSA-OAEP **невозможен**: схема рандомизирована, а фиксированный вектор требует закрытого ключа, которого для протокольного модуля у нас нет. Поэтому в `crates/crypto/src/raop.rs` остаются:

- SHA-256 отпечаток протокольного модуля `bcab8f19…791d0` — независимая константа (сверена с публичным ключом OwnTone `612d6b3c`);
- round-trip `OAEP-SHA-1` на локальной паре ключей (другая хэш-функция или метка не расшифруется) и проверка, что обёрнутый ключ ровно 256 байт.

Это проверяет параметры схемы, но не доказывает совместимость с конкретным приёмником. Независимый вектор появится только из захвата реального `ANNOUNCE`/`SETUP` с устройством.

## Ограничения

- Векторы SDP описывают нашу собственную форму объявления; они не доказывают, что реальный приёмник её примет. APEX/ATV ждут, возможно, другие комбинации `et`/`cn` и уровней `latency`.
- Шифрованный профиль проверен только сборкой строки; ключ не оборачивался под реальный протокольный модуль (закрытого ключа нет) и звук не отправлялся.
- Живой обмен RTSP с устройством не проверялся — аппаратная проверка открыта.
