# Владение пирами времени: lease и атомарная замена

Ветка `feat/peer-owner-leases`, база — `main` `b612eb4`, 2026-11-26.
Пункт **2** («Пиры, владение и восстановление») из P1-блока [AGENT-TASKS](AGENT-TASKS.md).

## Что было

`services/timesync/src/peer_interests.rs` уже объединял интересы нескольких
владельцев (`peer_union`), отвергал конфликт портов по одному адресу и
освобождал владельца только **явным** пустым списком. Отсюда две дыры:

- упавший потребитель (закрытый процесс, отменённая задача) держал своих
  пиров до остановки всей службы — срок у владения отсутствовал;
- объединение жило двумя копиями (`owners` + `peers`) внутри цикла, и
  корректность «план → применение → фиксация» держалась на дисциплине
  вызывающего, а не на типе.

## Что сделано

- **`OwnerInterests`** — реестр владения: владелец → список пиров + опциональный
  срок. `set(owner, peers, deadline)` сначала валидирует **весь** новый набор
  (объединение, конфликт портов, приватность адреса, IPv4/IPv6-совместимость,
  пределы 64/64) и только потом фиксирует; при ошибке не меняется ничего.
  Пустой список освобождает ровно этого владельца.
- **`Aggregate`** — единственная наблюдаемая форма: отсортированный союз
  `IP → порты`, номер поколения и `peers()` для движка. Частично применённого
  состояния наружу нет.
- **`expire(now)`** — тихий владелец исчезает так же, как при явном
  освобождении (срок включительно). Владелец без срока не истекает: это
  базовая пара службы (owner 0), а не группа.
- **`set_group_peers_for(owner, peers, Some(lease))`** в `Service`: срок
  взводится в момент вызова, а не в очереди; неограниченный lease отвергается;
  owner 0 по-прежнему зарезервирован для базового списка.
- Цикл службы на каждом тике (25 мс) вызывает `interests.expire(now)` и
  атомарно применяет изменившийся союз через `Engine::set_peers`.
  Расширение lease без изменения союза не порождает обновления движка и не
  двигает поколение.

## Проверки

```
cargo test --offline -p timesync --lib        -> 44 passed (5 новых в peer_interests)
cargo clippy --all-targets -p timesync -- -D warnings -> чисто
cargo fmt --check -p timesync                 -> чисто
```

Новые тесты: снятие одного владельца сохраняет общий с IP-адрес другого;
конфликт портов, мультикаст и неверный адрес не меняют ни союз, ни поколение,
ни число владельцев; владелец с истёкшим сроком исчезает, а владелец без срока
не истекает по времени; keepalive продлевает lease, не создавая нового
поколения; союз отсортирован и полон.

## Ограничения

- Loopback-тест истечения добавлен при интеграции; точность сетевых и аппаратных таймингов на устройстве не измерялась.
- Роль/lease самого PTP-выбора (`announce_lease_ns`) не менялись — это другой
  уровень; здесь только владение адресами получателей.
- Освобождение сокетов не менялось: пара 319/320 живёт, пока жива служба, в том
  числе при нуле пиров.
- Аппаратной проверки нет; несколько реальных RX/TX не подключались.
