# Живая группа и выбор колонок

Ветка `feat/live-group` от `origin/main` (`847fe38`). В `main` не влита.

## Что проверено

- Группа живёт в существующих `coordinator::runtime` (план выбора),
  `media::tx::pool::SessionPool` (физические сессии) и
  `sessions::output_worker` (адаптер). Второго менеджера сессий нет.
- Добавление колонки во время воспроизведения: `SessionPool::add/launch`
  подписывает новый воркер на тот же broadcast PCM, существующие не
  перезапускаются.
- Удаление колонки: `remove` останавливает только её, остальные продолжают
  получать пакеты (`continuous_fanout_shares_packets_and_removal_preserves_survivor`).
- Отказ одной колонки: воркер завершается `Failed`, соседние остаются
  `Running` и получают следующий пакет (`add_remove_and_failure_do_not_restart_surviving_receivers`).
- Ошибка подготовки новой сессии возвращается в `ApplyResult::start_errors`,
  не отменяя уже принятые изменения (`Runtime::apply_plan`).
- Смена endpoint/каталога не перезапускает активные сессии: активные строки
  закрепляются, новые адреса используются только для неактивных
  (`run_discovered`).

## Что добавлено

Тест `failed_member_is_replaced_without_restarting_survivor`:
сбойная колонка переходит в `Failed`, её удаление возвращает ошибку, но
освобождает место, после чего она подключается заново на тот же endpoint,
получает пакеты, а играющая соседняя остаётся `Running` и не перезапускается.

## Тесты

- `cargo test -p media` — 74 теста, все прошли.
- Clippy `-p media` — см. итог ветки.

## Ограничения

- **PTP-движок не менялся.** `SessionPool::sync_ptp_members` только сверяет
  список участников; реальная синхронизация группы без аппаратного теста не
  проверялась и не заявляется.
- «Отказ» здесь — ошибка воркера/соединения, а не обнаружение пропавшего звука
  по ушам; акустическая синхронность не измерялась.
- Автоматического переподключения нет: замена сбойной колонки выполняется
  явным решением вызывающего (повторный выбор/подготовка).
- Реальных колонок в окружении нет; всё проверено на тестовых воркерах.
