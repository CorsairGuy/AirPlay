# RAOP TX auth-setup: matrix and mock (D05, 28 ноября 2026)

Статус: **research/partial**, реализация в продукте не включена.

## Источник

OwnTone, commit `612d6b3cf34ae38bb71b6edfcd69fd7afe6ab25c`,
`src/outputs/raop.c`:

- `raop_send_req_auth_setup` — формирует запрос;
- `raop_cb_startup_options` — решает, когда его отправлять;
- разбор TXT `et` в `raop_device_start`/mDNS-обработчике;
- `raop_cb_startup_auth_setup` — что делать с ответом.

Это **отправитель** (клиент), а не приёмник. Наш основной RAOP-путь —
приёмник; матрица полезна только для будущего TX к внешним колонкам.

## Подтверждённые факты

| Условие | Факт в OwnTone | Следствие |
|---|---|---|
| OPTIONS 200 | `raop_cb_startup_options` читает `Public` | `POST` в `Public` — обязательное условие |
| TXT `et` | значение `4` выставляет `supports_auth_setup` | `et=4` — условие, а не доказательство работы |
| Порядок | OPTIONS → auth-setup → ANNOUNCE | auth-setup идёт до ANNOUNCE |
| Метод/URI | `POST /auth-setup` | не `SETUP`, не `OPTIONS` |
| Content-Type | `application/octet-stream` | бинарное тело |
| Тело | `0x01` + 32-байтный Curve25519 public key = 33 байта | `0x01` — флаг «без шифрования»; `0x10`, по комментарию, возможно шифрование |
| Ответ | не-200 только логируется, затем всё равно ANNOUNCE | успешный ответ не доказывает аутентификацию |
| Зачем | некоторым AirPlay 2 колонкам нужен этот шаг, иначе ANNOUNCE 403 | без захвата конкретной колонки включать нельзя |

OwnTone не проверяет сертификат/подпись и не выводит ключи из ответа: это
совместимость-заглушка, а не полноценный MFi auth. Наша реализация не должна
заявлять больше.

## Матрица решения для будущего TX

| `Public` содержит POST | TXT `et` содержит 4 | Действие |
|---|---|---|
| да | да | отправить auth-setup, затем ANNOUNCE; не заявлять шифрование |
| да | нет | сразу ANNOUNCE |
| нет | да | сразу ANNOUNCE; `et=4` без POST недостаточно |
| нет | нет | сразу ANNOUNCE |

Ответ `200` не меняет capability; ответ `4xx/5xx` не отменяет ANNOUNCE, но
должен быть виден в журнале без тела ключа. Реализацию включать только после
независимого захвата и с явным gate; сейчас в коде её нет.

## Mock-последовательность

Обезличенный fixture: `tests/interop/fixtures/raop-auth-setup.sequence`.
Публичный ключ заменён 32 нулевыми байтами, это не ключ устройства. Формат
строк — `>>` запрос, `<<` ответ; `\xNN` — байт. Fixture не подключён к
продукту и не является тестом совместимости.

## Ограничения

- Нет захвата реальной колонки, поэтому нет доказательства, что формат
  достаточно повторить для конкретной модели.
- Не реализованы Curve25519, сертификат, подпись и вывод ключей.
- Приёмный RAOP/iPhone-путь эта матрица не меняет.
