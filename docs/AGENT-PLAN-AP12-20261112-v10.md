## §6. MRP-чеклист аудита (D40, v2 — 13 пунктов)

Агент проходит по каждому пункту и фиксирует вердикт «ok / расхождение + файл:строка».
Референсы: pyatv (первичный), rust-atv/pyatv-rs (D41 — независимая Rust-проверка, нашла ошибки pyatv), node-appletv-remote (D13), edc.me «Dissecting the Media Remote Protocol» (OBS), golden-вектора D55.

1. **Framing**: длина сообщения — varint-префикс; всё — ProtocolMessage-конверт; identifier выставляется только на типах, ожидающих ответа.
2. **Первое сообщение**: DeviceInfoMessage в обе стороны ДО пейринга; после верификации все сообщения шифруются.
3. **Исключение CryptoPairingMessage**: ответ НЕ содержит identifier — позиция в пейринге определяется TLV-полем sequence внутри pairingData. Если код ждёт identifier в ответе на pairing — баг.
4. **Подписи**: pyatv ПРОПУСКАЕТ верификацию SRP proof, подписей pair-setup M6 и pair-verify M2 (RISKS.md M6, rust-atv). Для НАШЕГО приёмника это значит: сервер обязан корректно ФОРМИРОВАТЬ эти подписи — проверить их корректность на векторах pair_ap (D24).
5. **Туннелирование через AirPlay**: на tvOS ≥14.7/15 standalone-MRP спаривается, но команды вызывают новый PIN — управление работает только MRP-через-AirPlay. Для приёмника: корректно принимать MRP на data-канале AirPlay; семантика Command comm/cmnd (sender шлёт comm, receiver отвечает cmnd). Дополнение (RISKS.md M7): на современных сборках Companion — единственный путь пейринга, AirPlay-туннель аутентифицируется теми же HAP-креденшелами; зафиксировать в SESSION_PROFILES, по какому пути реально ходит клиент.
6. **Подписка**: ClientUpdatesConfigMessage сразу после верификации — без неё нет SET_STATE_MESSAGE.
7. **Порт MRP меняется в любой момент** (после ребута и в случайные моменты) — re-advertise через mDNS обязателен.
8. **Unknown fields (D49)**: не отбрасывать и не падать на неизвестных полях; в реле не пере-сериализовывать — пересылать исходные байты. ОБЯЗАТЕЛЬНЫЙ аудит: какой protobuf-крейс в crates/mrp — prost не хранит unknown fields (потеря при decode→re-encode гарантирована), rust-protobuf хранит (UnknownFields), buffa заявляет round-trip fidelity. Результат аудита — в WIRE-SPEC/SECURITY.
9. **supportedCommands**: карточка обязана анонсировать набор команд с enabled и preferredIntervals; pyatv считает отсутствующие команды недоступными — это видят все клиенты.
10. **PlaybackQueueRequestMessage**: реальные клиенты iOS шлют его 1–2 раза в секунду — приёмник должен отвечать быстро, иначе UI карточки лагает/стопорится.
11. **SET_STATE_MESSAGE приоритет и errorCode**: проверять обработку errorCode: NoError и поле priority.
12. **Обложки**: сверка формата image params (width/height) с clientCapabilities (D12 §3.3).
13. **AudioRoute.proto (RISKS.md L12, rust-atv)**: vendored AudioRoute.proto в pyatv МОЛЧА ТЕРЯЕТ now-playing метаданные на tvOS 27. Значит: (а) наша схема сверяется по mediaremote-server (кросс-чек 3.1), НЕ по pyatv-схеме; (б) если pyatv-конформанс покажет отсутствие now-playing — это может быть баг PYATV, а не наш. Помнить при трактовке strict-decoder.

Критерии закрытия D40: чеклист пройден по коду; каждый пункт — с выводом «ok / расхождение + файл/строка»; расхождения — в отдельный список с приоритетом; результат аудита п.8 — записан в WIRE-SPEC/SECURITY.
