# Кнопка группы/ретрансляции: эксперименты

<!-- current-status-20261112 -->
> Сверено 12 ноября 2026. Текущий статус и ограничения — [STATUS](STATUS.md). Все физические захваты требуют отдельного разрешения; на Станции ничего не устанавливается и не меняется без согласия.

## Правила

- Соглашения по дескрипторам меняются только после эталонного захвата реального группового устройства. Без него любые правки дескрипторов — гадание.
- Транспорт (SETPEERS/PTP) проверяется отдельно от кнопки. Один эксперимент не проверяет звук и UI одновременно.
- Объявление возможностей не заменяет проверку транспорта; ACK и галочка интерфейса не доказывают adoption (SESSION_PROFILES, PROTOCOL).
- Гипотезы о форме сообщений проверяются строгим декодером по образцу pyatv-ловушки ведущего `0x08`: лишний порядок полей или неверный repeated/singular выбор теряет сообщения без ошибки.

## Составные каналы кнопки

Кнопка группы в карточке iPhone требует совпадения четырёх независимых каналов. Отказ любого даёт один и тот же симптом — одинарная кнопка:

1. **Discovery**: TXT-флаги `igl`/`gcgl` в `_airplay._tcp`. Наблюдение 30.10: флаги видны в Bonjour и отсутствуют в `/info`; роль группы живёт в объявлении, не в сессии (см. wire-spec).
2. **MRP**: дескрипторы топологии в deviceInfo — `logicalDeviceCount`, `groupedDevices`, выбранный дескриптор, идентификаторы участников.
3. **Межустройственная согласованность**: каждый участник группы сам объявляет ту же группу — те же ID и состав. Рассинхрон участников даёт iOS два независимых лидера без основания сворачивать их в одну кнопку.
4. **Push-семантика**: изменения топологии дублируются обновлениями канала, а не отправляются один раз при подключении.

## Что уже известно из захватов

- Снимок station-ht-0633 уже содержит `logicalDeviceCount=2`, `groupedDevices` и выбранный Home Theater дескриптор при сохраняющейся одинарной кнопке. Добавление имени или счётчика — не доказанный фикс.
- hp121-stationsess-0633 рекламирует собственную theater-группу, Станция — собственную relay-группу: рассинхрон между участниками зафиксирован в исторических захватах. Эти срезы предшествуют последующей PTP-работе и не доказывают текущее состояние приёмника.
- Требуются датированные date-matched MRP/mDNS наблюдения либо более поздний захват до изменения group IDs.
- Синхронизация звука не равна принятию топологии; не смешивать.

## Гипотезы (порядок вероятности)

1. Рассинхрон участников: лидер и член рекламируют разные группы (прямо задокументировано в захватах).
2. Форма дескриптора: repeated vs singular поля, типы идентификаторов, вложенность под-сообщений, ведущие байты.
3. Пуш вместо снапшота: дескриптор отправляется один раз при подключении; открытая карточка не подхватывает изменение.
4. Нестабильность ID: group ID и идентификаторы участников генерируются заново при каждом старте; iOS видит «новое устройство».
5. Гейтинг по клиенту: форма и наличие group-UI зависят от clientCapabilities конкретной iOS-версии.

## Лестница

**Шаг 0 — эталонный захват.** Реальная группа двух HomePod: TXT обоих участников до и после группировки, `/info` обоих, полный MRP-сеанс iPhone в моменты переключения кнопки (включая открытие карточки и повторное открытие). Всё датировано, сохранено в workspace с указанием устройств. Критерий: файлы захвата существуют, датированы, привязаны к устройствам.

**Шаг 1 — побайтовый дифф.** Сравнение собственного дескриптора с эталонным поле за полем: порядок, типы, repeated-структуры, значения ID. Результат — таблица RE/OBS/UNKNOWN по полям. Запрещены формулировки вида «выглядит похоже».

**Шаг 2 — согласованность двух своих приёмников без iPhone.** Два собственных приёмника объявляют идентичные группы друг другу: одинаковые ID на обоих, состав в дескрипторах совпадает с TXT. Проверяется сверткой TXT+MRP обоих участников между собой. Кнопка на iPhone здесь — первый физический тест, а не первый шаг.

**Шаг 3 — push-семантика.** Изменение топологии дублируется обновлением канала по образцу уже исправленной карточки (UpdateContentItem вместо набитого заново SetState): обновлять состояние, а не пересылать слепок.

**Шаг 4 — критерии закрытия.** Физически подтверждены: общая подпись кнопки в реальной группе, удержание ползунков, переключение группы туда и обратно. До этого эти пункты остаются в VALIDATION как «не подтверждено».

## Границы

- Транспорт и UI не смешиваются в одном эксперименте.
- Захваты выполняются только при отдельном разрешении.
- Baseline записывается до любых изменений advertisement (правило перенесено из плана Yandex Music).
- Результаты шагов заносятся в VALIDATION с датой и условиями, не в этот документ как «выполнено».
