# Внешние профили устройства

> Историческая заметка о реализации. Сведения о базе ветки и тестах ниже относятся к моменту написания; текущее состояние — в [STATUS](STATUS.md).

Ветка `feat/device-profiles` от `main` (`847fe38`), на дату заметки ещё не влита. Убран
единственный зашитый набор имени/модели/флагов: приёмник может взять их из
plist-файла, не пересобирая программу. Windows-интерфейс не менялся.

## Формат

`airplay --profile ПУТЬ` читает XML- или binary-plist со словарём:

| Ключ | Тип | Обязателен | Проверка |
|---|---|---|---|
| `name` | string | нет | непустая, ≤ 64 байт |
| `model` | string | да | ASCII, ≤ 64 байт |
| `features` | integer или `"0x..."` | да | не 0; бит SCREEN требует `display` и наоборот |
| `status_flags` | integer | нет (0x404) | ≤ u32 |
| `source_version` | string | нет (366.0) | цифры и точки, ≤ 32 |
| `accessory_type` | integer | нет | идёт в TXT `at` |
| `display` | dict `width`/`height`/`fps` | при SCREEN | 1..7680, fps 1..120 |
| `audio_only_ui` | boolean | нет | карточка MRP всё равно требует `--mrp` |
| `enclosure_color` | string | нет | ≤ 32 байт |
| `raop` | boolean | нет (true) | `false` — объявлять только `_airplay._tcp` |

Неизвестные ключи и ключи неизвестного типа отклоняются: опечатка в профиле
не должна молча превращаться в другое устройство. Значения профиля заменяют
соответствующие параметры командной строки (`--model`, `--features` и т. п.);
это указано в `--help`.

Примеры: `docs/profiles/speaker.plist` (AirPort, колонка без экрана),
`docs/profiles/tv.plist` (экран 1920×1080@60) и `docs/profiles/mac.plist`.
Это описания того, чем приёмник представляется, а не заявление о
реализованных возможностях: маска не делает поддержанным то, чего нет в коде.

## Названия и источники профилей

Выбор и настройки профилей принадлежат приложению; ядро предоставляет разбор внешнего plist и механизмы протокола. Имена ниже — согласованные названия, а не идентичности реальных устройств; собственные идентификаторы и ключи не заменять снятыми с устройств.

| Название | Основа и состояние |
|---|---|
| **AirPort** | Существующий пример `profiles/speaker.plist`, модель `AirPort10,115`. Переименовано отображаемое имя, параметры сохранены. |
| **HomePodMini** | Профиль Станции: модель `AudioAccessory5,1`, версия `550.10` в её `station/data/local/bin/airplay_audio.sh`. Полную маску и остальные поля работающего объявления нужно отдельно извлечь из проверенной сборки Станции; готовый профиль пока не заявлен. |
| **AppleTV** | Запись реальной Apple TV 4K: `AppleTV14,1`, `960.13.1`, объявленные `features=0x3C177FDE4A7FDFD5`, `statusFlags=0x10644`; см. [запись](MIRRORING-AIRPLAY2-RESEARCH.md). Это наблюдение устройства, не подтверждение поддержки этих возможностей ядром. Готовый профиль для объявления появится после сверки полей с реализованными режимами и проверки с iPhone. |
| **OtherTV** | Исторический профиль Windows-зеркалирования, проверенный с iPhone: `profiles/other-tv.plist`, модель `AppleTV3,2`, `features=0x8300527FFEE6`, `status_flags=4`, `accessory_type=1`, версия `550.10`. Он вдохновлён LG-тестами, но не является копией TXT реального LG. Прежняя проверка не подтверждает PTP или работу текущего main без повторного испытания. |

`profiles/tv.plist` — старый общий пример, не профиль **AppleTV** из пользовательской записи. Нельзя автоматически принимать его за современную приставку или за **OtherTV**.

## Изменения

- `crates/device/src/profile.rs` — загрузка, строгий разбор и валидация.
- `DeviceInfo.raop` — профиль может выключить `_raop._tcp`;
  `sessions::Context::services` учитывает это.
- `serve::Options.profile` и `--profile` в разборе аргументов.

## Тесты

`cargo test --offline -p device -p sessions -p airplay`:

- device: 8 тестов, включая разбор трёх примеров, hex-маску, отказ для
  неизвестного ключа, неверной версии, `display` без бита SCREEN, нулевой
  маски и неверного типа `raop`.
- sessions: 23 теста, включая `profile_can_leave_only_the_airplay_service`.
- airplay: 4 теста, включая загрузку `tv.plist` через `--profile`.

`cargo clippy --offline -p device -p sessions -p airplay --all-targets` — без
новых предупреждений.

## Границы

Другие примеры не проверялись с реальным iPhone/Apple TV. Исторический
результат OtherTV описан выше; его перенос в текущий runtime и дальнейшие
комбинации возможностей требуют отдельной аппаратной проверки.
