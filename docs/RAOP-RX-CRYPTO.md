# RAOP RX: что известно о шифрованном звуке

Исследование по v12 D23/D45/D47, [RAOP-RX](RAOP-RX-20261125.md) и закреплённым
референсам (OwnTone `612d6b3cf34ae38bb71b6edfcd69fd7afe6ab25c`, shairport-sync 5.6.3).
Разделены проверенные шаги и шаги, для которых нет захвата или ключа.

## Подтверждённые шаги

| Шаг | Доказательство | Состояние |
| --- | --- | --- |
| Обёртка ключа отправителя: RSA-OAEP/SHA-1, модуль 1024 бита, экспонента 65537 | публичный ключ приёмника из RAOP; `crates/crypto/src/raop.rs`, хэш модуля совпадает с OwnTone | реализована отправка (`wrap_key`), только TX |
| AES-128-CBC на каждый аудиопакет заново, IV из `aesiv`, шифруются целые блоки, хвост открыт | `crates/crypto/src/cbc.rs`; вектор NIST SP 800-38A F.2.2 и независимый вектор OpenSSL 3.5.9 | примитив реализован и проверен |
| `a=et:` — объявление профилей, а не решение о шифровании; `et:0,1` без ключей — открытый поток | разбор `handle_announce` в shairport-sync 5.6.3 | реализовано в `parse_sdp` |
| Признак шифрования — `rsaaeskey`/`fpaeskey`/`aesiv`, а также `et` без `0` | там же | такие `ANNOUNCE` получают 501 |

## Отсутствующие шаги

| Шаг | Почему не реализован |
| --- | --- |
| Расшифровка `rsaaeskey` на приёмнике | нужен закрытый ключ, соответствующий опубликованному `pk` приёмника. У проекта есть только публичный протокольный ключ Apple для TX; приватного ключа нет, подделать его нельзя |
| Формат `rsaaeskey` для RAOP (длина, порядок байт, OAEP или PKCS#1) | нет захвата `ANNOUNCE` с реальным ключом; длины в источниках расходятся, вывод по имени поля запрещён |
| Смещение аудиоданных в расшифрованном пакете (служебные байты перед кадрами ALAC) | нет пары «шифротекст → известный PCM»; без неё нельзя утверждать, что первые байты — заголовок |
| Повторное шифрование и AAC-ELD | вне рамок AirPlay 1 RAOP |

## Что это значит

Приёмник принимает только открытый профиль. `SETUP` с `rsaaeskey`, `fpaeskey`,
`aesiv` или `et` без `0` отклоняется на `ANNOUNCE` с 501, формат сбрасывается,
следующий `SETUP` снова требует `ANNOUNCE`. Тишина вместо звука не выдаётся за
совместимость, защищённый поток не рекламируется.

## Тесты

- `cargo test --offline -p crypto --lib cbc` — NIST-вектор, вектор OpenSSL, открытый
  хвост, пустой ввод, неверный ключ.
- `cargo test --offline -p crypto --lib raop` — хэш протокольного модуля, длина
  обёрнутого ключа 256 байт, round-trip OAEP/SHA-1 на тестовой паре.
- `cargo test --offline -p media --lib raop` — `encryption_is_rejected_not_ignored`,
  `rejected_announce_clears_previous_format`.

Ни один из тестов не является проверкой с реальным отправителем.
