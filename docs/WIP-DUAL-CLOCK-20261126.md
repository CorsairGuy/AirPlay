Изначальный вариант `feat/dual-clock-roles` объединял адреса источников и получателей, поэтому исходящий master мог слать Sync самому источнику. В этом черновике раздельные peer interests для входящих сессий и исходящих групп; пересечение по IP отклоняется, источники обновляются через `set_session_peers`, группы — через `set_group_peers`. Проверить сквозным тестом композицию `TimeSync::start_host_dual`, `dual_clock_source` и `MasterTimeline`, пригодность API для фронтенда и отсутствие регрессий одноролевого режима.
