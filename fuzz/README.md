# Fuzz-корпус сетевых парсеров

Небольшой набор заведомо некорректных входов, которые приёмник получает
из сети: RTSP-заголовки и тела, TLV8 сопряжения, plist и RTP. Файлы
синтетические: ни ключей, ни адресов реальных устройств, ни личных данных.

Корпус прогоняется обычным тестом — `bin/airplay/tests/input_corpus.rs`,
без `cargo-fuzz` и без сети:

```
cargo test -p airplay --test input_corpus
```

## Классы

| Каталог | Что проверяется |
|---|---|
| `corpus/rtsp` | `Content-Length` (отрицательный, `+12`, переполнение, двойной, незавершённое тело), отсутствие `\r\n\r\n`, мусорная стартовая строка, заголовок без двоеточия, не-UTF-8 и NUL в заголовке, пачка запросов подряд |
| `corpus/tlv8` | обрезанный TLV, пустое значение, неизвестное состояние, значение длиной 255+ байт, «вложенный» TLV внутри значения |
| `corpus/plist` | глубокая вложенность XML и бинарного plist (1000 уровней), циклическая ссылка объекта, счётчик объектов больше файла, обрезанный `bplist00`, не-plist |
| `corpus/rtp` | короткий пакет, только заголовок, обрезанный шифротекст, префикс длины 2 и 0xFFFF |

## Как пополнять

Кладите файл в нужный каталог; тест подхватит его сам. Имя файла должно
описывать класс ошибки. Ожидания для `corpus/plist` — только отказ
(`rtsp::plist::parse` → `None`); для остальных каталогов достаточно, чтобы
разбор вернул ошибку/`None` без паники и зацикливания.

Корпус не заменяет полноценный фаззинг: он фиксирует уже разобранные
классы ошибок и защищает от их возврата. Настоящий `cargo-fuzz` потребовал
бы nightly и отдельной сборки, поэтому здесь его нет.
