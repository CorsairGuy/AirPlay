# Changelog

## Unreleased

- AirPlay 1 sender: a separate RAOP profile now parses `_raop._tcp` TXT, negotiates PCM or uncompressed ALAC, performs OPTIONS/ANNOUNCE/SETUP/RECORD, sends RTP audio (optional AES-CBC), sets volume and tears down. A local fake receiver verifies the sequence, SDP, volume body and decrypted ALAC payload. RSA key exchange, NTP anchoring and hardware compatibility are explicitly not implemented.
- Live group: verified join/leave and per-speaker failure through the existing SessionPool; a failed member can be removed and rejoined on the same endpoint without restarting surviving receivers. PTP is unchanged and no acoustic synchronization was measured.
- MRP card: a reconnecting controller now receives the current track snapshot on subscribe instead of waiting for the next sender event; added tests for artwork replacement/cleanup, pause/resume and reconnect. Verified with the test client only, not an iPhone.
- Reconnect (S3/S4/S6): dropping a session without TEARDOWN now clears the sender group and card state, so an abrupt disconnect or network change no longer leaves a stale gid; added a reconnect test that opens a new SETUP on the same context. No automatic reconnect or Station route changes; long half-open socket detection remains with the OS.
- Remote control: MRP SendCommand now deduplicates retransmitted request identifiers (bounded to 64 IDs) without suppressing real repeats under a new identifier, and event-channel loss detaches the remote without replaying queued commands. Legacy DACP remains a separate protocol path, not aliased to MRP. Protocol tests only; no hardware remote was available.
- RTP receive (S13): duplicate packets no longer overwrite the queued payload, and packets at or before the played-through timestamp are not requeued. The bounded 4096-packet buffer and resync deadline are covered by new tests. TX-side retransmission is still absent; no hardware audio check was performed.
- Sender latency: an externally configurable LatencyPolicy now intersects the requested delay with the receiver SETUP latencyMin/latencyMax, rejects contradictory or non-overlapping ranges, and supports a bounded pre-RECORD initial buffer. This is calculated latency, not a measured acoustic delay; NTP/PTP is unchanged.

- HLS seek clears buffered audio; multichannel HLS audio is rejected rather than silently dropping channels. A replacement buffered-audio connection must deliver an authenticated packet before replacing the active reader; replay protection remains outside this change.

- Fixed audio receive defects that caused silence or a stuck session: realtime UDP datagrams were truncated at 2048 bytes (an ALAC 24-bit packet is 2156), a second buffered TCP connection was not accepted while the previous one stayed open, an unknown SSRC stalled playback permanently, the packet queue and the partial-packet buffer had no bound, `recv` errors spun a busy loop, and a failed decoder was recreated on every packet. End-to-end tests in `crates/audio_stream/tests/pcm.rs` send known AAC/PCM and compare the PCM that reaches the sink; the realtime path is covered with PCM because no ALAC encoder is available, so ALAC playback still needs an iPhone check.
- FairPlay v2 (`request[4] == 0x02`, macOS Music) is rejected with a distinct `UnsupportedV2` error instead of a generic version error, and the v3 path is covered by regression tests. v2 itself is not implemented: its SAP transform is only available as third-party derived constants, so the gap list, provenance and Mac capture plan live in `docs/FAIRPLAY-V2.md`.
- Extracted the receiver from `bin/airplay` into the service crates: the RTSP session, connection transport and output worker now live in `sessions`; `Player`, stream SETUP, the event channel, the sender control channel and MRP channel plus HLS options in `media`; the MRP card, its server, output queue and output selection in `remote`. The binary keeps argument parsing, composition, mirroring video output, PTP groups and the `send` CLI. Cycles are broken by small interfaces (`media::control::MrpHandler`, `media::rx::SessionGroup`, `media::rx::MediaContext`) rather than wrappers, and the old receiver, session and remote wrapper paths are removed. The cross-crate MRP authorization test moved to `bin/airplay/tests/authorization.rs` so `remote` no longer needs `sessions` in its test build.
- PIN pairing sends `X-Apple-Client-Name` on the initial and setup requests; callers can supply a display name or use the existing API's `AirPlay` default. Hardware validation with Apple TV remains outstanding.
- HLS VOD now decodes audio and video against one presentation clock (the audio sink paces playback and the picture follows it) and adds pause/resume, segment-granular seek (`/scrub`, `/play` `Start-Position-Seconds`) and an explicit stop; the FFmpeg path and AirPlay routes are covered by loopback HTTP tests with local media, including a truncated segment and a reconnect. Live refresh, DRM/FairPlay, frame-accurate seek, forward buffering and capability advertisement remain unsupported, and no iPhone validation has been performed.
- HLS playback now owns its lifecycle: stop and seek abandon the segment producer and its blocking decoder instead of leaving a `spawn_blocking` decode running behind an aborted task, and a download failure surfaces as itself rather than as a demux error or a false success.
- Moved output-selection precedence and logical-to-physical resolution into `services/coordinator`. MRP output-context decoding and its request queue now sit under the application's `remote` component; the serialized worker applies coordinator decisions to discovered, authorized media sessions.
- Discovery now owns the validated logical/physical output snapshot; `media::tx::SessionPool` exposes only physical session membership and operations. Coordinator runtime state and plan application use discovery/session backend interfaces, avoiding coordinator-to-media/discovery dependencies; the app remains responsible for authorization and session preparation.

- Moved media events, local output process and source supervision from the binary crate into the media service. Existing public module paths are re-exported; receiver session and MRP orchestration remain in the binary library until their dependency cycle is removed.

- Moved actual implementation into seven service packages: discovery, sessions, timesync, media, remote, coordinator and identity. Session preparation, identity and discovery have dedicated packages; part of receive-session and remote runtime wiring remains in the binary library.

- Renamed the 20 `ap_` library packages to their unprefixed names. Compatibility re-export packages retain `ap_sender` and `ap_mrp`; the transport itself is `media::tx`. Other old Cargo package names change.
- Removed NQPTP-specific ABI, reader and control adapters from the core. Existing Station integration is pinned to its earlier revision and must be adapted before updating; the in-core PTP engine is not yet validated as complete.
- Moved existing application modules under discovery, sessions, identity, coordinator, remote and media rx/tx/output. Internal imports use the new boundaries; prior Rust module paths remain available for external compatibility. The group state, output selection and volume model live in the coordinator library; media::tx owns sender transport and session pool. This does not add processes or claim completion of MRP consolidation.
- Native PTP peer interests are retained per session, so removing one session does not discard another session’s peers. The RTSP sender is retained as a timing peer even if timingPeerInfo is absent. PTP operation with real AirPlay devices still needs validation.

- Added configurable AirPlay feature mask, status flags, and accessory type to the receiver. Device profiles are chosen by the caller, independently of any Windows application.
- Investigated approximately 7.4–8.4 s between an observed mDNS query and RTSP startup. In the tested TV receiver, clearing feature bit 48 while retaining bits 40, 41, and 47 (`0x527FFEE6,0x8300`) produced immediate video with a TV icon; repeated connections after resetting iPhone Wi-Fi also succeeded. Restoring bit 48 while clearing bit 47 restored the delay. These observations identify a trigger in this profile, not the iPhone's internal mechanism.
- A pre-RTSP PTP probe was not observed on the tested PC interface; toggling bit 41 did not remove the delay. Removing buffered-audio bit 40 made video fail, so it is not a viable fix. Changing source version (550.10, 220.68, 377.40.00) or omitting TXT `at` did not yield a reported speedup. In one capture, no PC mDNS reannouncement was observed in the pause and Fast/TV PTR, SRV, and TXT TTL and cache-flush settings matched. These network observations are limited to traffic visible to the PC; they do not establish AWDL behavior.
- Open: why iPhone waits when bit 48 is advertised in this profile. The successful mirror session selected NTP even though bit 41 remained advertised; actual PTP operation and relay timing remain separate work.
